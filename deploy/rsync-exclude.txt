# Exclusions du déploiement par rsync, à passer avec --exclude-from :
#
#   rsync -avz --exclude-from=deploy/rsync-exclude.txt . serveur:/srv/webs/dolinews.com/app/
#
# Chaque ligne porte sa raison : en retirer une suppose d'avoir relu la
# sienne. Les motifs commençant par / sont ancrés à
# la racine du transfert, les autres s'appliquent à n'importe quel niveau.
#
# Un fichier exclu est aussi protégé côté serveur : RSYNC_DELETE=--delete ne
# supprime pas ce qui correspond à l'une de ces lignes.

# Le lien du disque public. rsync -a implique -l et recopie le lien TEL QUEL :
# il arrive sur le serveur en pointant vers le chemin de la machine source,
# donc mort, et Apache répond alors 403 - et non 404 - sur chaque image de
# chaque article. Le serveur refait le sien avec `make storage-link`.
/public/storage

# Tout ce que le serveur écrit lui-même et qui n'a pas d'équivalent ici :
# journaux, médias déposés par l'API, sessions, vues compilées, cache.
# Sans cette ligne, honeypot.log de la machine de développement remplace
# celui de la production - nouvel inode, contenu antérieur - et fail2ban y
# perd sa position sans le signaler : la prison reste active et ne compte
# plus rien. Les 28 Mo de laravel.log d'un poste de développement y passent
# aussi, par-dessus le journal du serveur.
/storage

# Config et services compilés. Copiés depuis ici, ils portent APP_ENV=local,
# les chemins de cette machine et la base SQLite de développement : entre le
# rsync et le `make cache` qui les reconstruit, le site sert avec la
# configuration du poste de développement.
/bootstrap/cache

# Dépendances PHP. Celles du poste de développement incluent les paquets de
# dev (pest, phpstan, pint) : envoyées, elles écrasent le vendor du serveur,
# le site tourne dessus jusqu'au `make all`, puis `composer i --no-dev` les
# supprime aussitôt. 166 Mo transférés pour rien. Le serveur installe les
# siennes depuis composer.lock.
/vendor

# Assets construits. `make prod` les reconstruit sur le serveur ; public/hot,
# présent pendant un `npm run dev`, ferait charger chaque page de production
# depuis le serveur Vite du poste, donc sans feuille de style ni script.
/node_modules
/public/build
/public/hot
